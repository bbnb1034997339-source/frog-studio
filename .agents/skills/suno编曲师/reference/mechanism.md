# Suno 生成机制(为什么这么写)

理解机制,才知道写法背后的"为什么"。suno.cn 与 Suno 同源,以下原理通用。

## 1. 共现机制(co-occurrence)—— 一切策略的根源

Suno 不像人那样"读懂"指令,而是按训练数据里的**统计关联**混合风格。

- **流派云**:风格不是孤立的。要 `rap` 会自动带出 trap / hip-hop / bass / 808 beat,因为它们在训练里总一起出现。要纯粹的某种风格,常需**显式排除杂质**(在风格框描述里加否定句,如 `no trap, no 808`,或正向描述把方向钉死)。
- **含义**:风格框里每个词都带"统计包袱"。写 `boom bap` 可能仍混进 trap 味,除非明确反向拉。

**对策**:用**具体、抽象、可组合**的特征(流派+年代+配器+情绪),而不是模糊形容词或人名。

## 2. 描述式写法为主(已按实战修正)

旧说法"逗号短标签 > 散文"是 v3.5 时代的。**V4.5 / V5.5 + 1000 字风格框**对**描述性自然语言**解析很好,尤其**嗓音质感、乐队风格、制作细节**这类需要"绕着说"的东西,描述性写法更准。

- **风格框**:**全部用描述性自然语言写**——写完整句子描述"声音长什么样",不罗列单词标签。句子能把"什么乐器 + 什么质感 + 什么情绪 + 怎么演奏"串成有画面的声音描述,模型理解更准。
- **结构标签**:仍用**精确标签格式**(`[Verse]`、`[Chorus]`)。要避免的风格没有单独框,直接在风格框描述里加否定句。
- **关键区分**:描述要是**"声学描述"**(口音/鼻音/咬字/音域/唱腔/配器/年代/制作),**不要写成"叙事抒情"**——后者才会触发下面的歌词泄漏。

详见 `reference/style-field.md` 的「描述性写法 & 风格/嗓音模仿」。

## 2b. 歌词泄漏(lyric bleed)

**叙事/抒情**式的模糊散文,容易被模型当成**歌词唱出来**;但**声学特征描述**不会。

- **对策**:风格框写"声音长什么样",不写"故事/心情";圆括号 `()` 里的内容会被当 **ad-lib 唱出**(这也是咬字标注不能用内联括号的原因)。

## 3. 人名/乐队名:翻译成声学特征

周杰伦 / Blur / Taylor Swift 等**直接写常被版权过滤或忽略,不可靠**。但把那个人/乐队的**"声音指纹"翻译成可描述的声学特征,最稳也最准**。

- 例:别写 "Blur 的嗓音" → 写 `A 90s Britpop track with jangly distorted guitars, driving bass, and live drums. The male vocal is slightly nasal with a laid-back, cheeky cockney-tinged drawl — melodic and conversational. Lo-fi analog warmth.`
- 例:别写 "像朴树" → 写 `A 90s Chinese indie folk track with a warm, slightly raspy male vocal delivered in a plain-spoken, understated way. Fingerstyle acoustic guitar, nostalgic tone.`

## 4. 风格框 vs 歌词框 —— 分工

| | 风格框(Style) | 歌词框(Lyrics) |
|---|---|---|
| 管什么 | 声音世界:流派/配器/速度/情绪/人声/质感 | 唱的字 + 结构骨架 + 段落级局部指令 |
| 作用域 | **全局**(整首) | **局部**(元标签覆盖所在段的全局风格) |
| 语言 | **英文** | 中/英/混(直接写) |
| 会被唱吗 | 否 | 是(含圆括号 ad-lib) |

**原则:风格框定调,歌词框排兵布阵。**
- 整首男声 → 风格框;副歌突然切女声/变激烈 → 歌词框那段前。
- 慵懒、真人感、避免舞曲鼓 → 风格框;某段渐强/加 solo/气声 → 歌词框对应位置。

## 5. 去 AI 味(本项目硬要求)

AI 味的常见来源与对策:
- **念白**:Suno 干声口语缺少旋律和节拍约束,最容易机械假。优先转成 melodic rap、窄音域 talk-singing 或 rhythmic chant;真正旁白用真人录音合入。
- **过整齐的字数**:每行一样长 → 机械感 → **行内错落**。
- **舞曲化重复鼓点**:四平八稳 four-on-the-floor → 单调 → 风格框写 `syncopated / loose / live drums`,避免 `dance beat`。
- **过完美**:不要只加形容词。写清合理换气、稳定 pocket 中的乐手前后关系、乐器在句间回应、统一录音空间和保留动态;只选 1-2 项受控不完美。详见 `performance-realism.md`。
- **生僻/拗口字**:咬字翻车暴露 AI → 用可唱的字 + 同音替换(见 lyrics-craft)。

## 6. 迭代,而非一击必杀

Suno 有随机性。同一套提示词多生成几版挑最好;跑调时换 Key(±2-3 半音)往往比堆提示词有效;弱段可在「处理已有歌曲」里用 扩展 / cover / 添加音轨 兜底重做(suno.cn 实测功能)。
